# Data Model: メガミンクスの最後の層の画像ライブラリ（megaminx-image）

公開するもの（✅）と内部だけのもの（🔒）を分けて書く。公開するものの正確な形は `contracts/api.md`。

## 面（Face）✅

- 12 面：`U` `F` `R` `BR` `BL` `L` `DR` `DBR` `B` `DBL` `DL` `D`
- 上段（上から見て反時計回り）：`F` `R` `BR` `BL` `L`／下段：`DR` `DBR` `B` `DBL` `DL`／底：`D`
- 回転記号ではこのほかに持ち替え `y` を読む（面ではないので配色には出てこない）

## 色（Color）✅

- 1 文字の色コード 15 個、または `#rrggbb`（大文字・小文字どちらも可。出力では小文字にそろえる）

| コード | 色 | 16 進 |
|---|---|---|
| `d` | 暗い灰色（dimgray） | `#696969` |
| `u` | 薄い灰色（lightgray） | `#d3d3d3` |
| `p` | ピンク（pink） | `#ffc0cb` |
| `c` | レモン色（lemonchiffon） | `#fffacd` |
| `a` | 水色（aqua） | `#00ffff` |
| `o` | オレンジ（orange） | `#ffa500` |
| `l` | 黄緑（lawngreen） | `#7cfc00` |
| `b` | 青（dodgerblue） | `#1e90ff` |
| `y` | 黄（yellow） | `#ffff00` |
| `s` | 紫（darkviolet） | `#9400d3` |
| `g` | 緑（seagreen） | `#2e8b57` |
| `r` | 赤（red） | `#ff0000` |
| `w` | 白（white） | `#ffffff` |
| `x` | 黒（black） | `#000000` |
| `z` | ほぼ黒 | `#1b1b1b` |

- 検証：上の 15 文字（小文字だけ）か `/^#[0-9a-fA-F]{6}$/`。それ以外（色の名前・`#fff`・大文字の `O` など）は
  `TypeError: Unknown color: "…"`

## 配色（Scheme）✅

- 面 → 色 の対応。一部の面だけでもよい（使う面が無ければ、そのときにエラー）
- 既定の配色 `DEFAULT_SCHEME`：U `u`・F `a`・R `o`・BR `l`・BL `p`・L `c`・DR `s`・DBR `y`・B `b`・DBL `r`・
  DL `g`・D `w`
- OLL 用の配色 `ollScheme(scheme?)`：U は渡した配色（既定は `DEFAULT_SCHEME`）の U の色、ほかの 11 面は `d`
- 検証：知らない面の名前は `TypeError: Unknown face: "…"`、色は上の検証。画像に出てくる面が配色に無ければ
  `TypeError: No color set for face: X`

## 手順（Alg）✅（文字列）／ 🔒（読んだ形）

- 公開は文字列だけ。記法は `contracts/notation.md`
- 内部の読んだ形：`Move = { face: Face | 'y', turns: 0..4 }`（時計回り 72° 単位）の列。括弧は読んだときに展開する
- 道具（✅）：`canonicalAlg`（記号を正しい表記に）、`invertAlg`（逆の手順）、`simplifyAlg`（まとめる）。
  どれも読めない手順は読むときと同じ `SyntaxError`

## 内部の状態（State）🔒

- 132 枚（12 面 × 中心 1・辺 5・角 5）の、それぞれの位置にある色の元の面。サイトと同じ並び・同じ作り方
- 揃った状態 → `start` の手順を回す → alg（手順を回す）か case（逆を回し、持ち替えの合計を打ち消す）
- 公開しない（あとで全体の展開図を足すときに変えられるように。原則 V・VII）

## ステッカーの色の並び（StickerColors）✅

- 26 個の色の配列。並び順はサイトと同じ（仕様 FR-026）。画像の上の頂点を 0 とし、反時計回りに頂点 0〜4、
  頂点 k と k+1 の間を辺 k（辺 2 が手前＝F 面）

| 番号 | ステッカー |
|---|---|
| 0 | U 面の中心 |
| 1 + 2k（1, 3, 5, 7, 9） | U 面の角（頂点 k） |
| 2 + 2k（2, 4, 6, 8, 10） | U 面の辺（辺 k） |
| 11 + 3k | 辺 k の側面の上段の左の角（外から見て） |
| 12 + 3k | 辺 k の側面の上段の辺 |
| 13 + 3k | 辺 k の側面の上段の右の角 |

- 揃った状態・既定の配色では、辺 2（番号 15〜17）が F 面の `a`
- 出力の色は、配色・上書き・直接指定で渡した形のまま（色コードは色コード、`#rrggbb` は小文字の 16 進）
- 直接指定（`state`）は、ちょうど 26 個でなければ `RangeError`。上書き（`stickers`）の番号は 0〜25 の整数で
  なければ `RangeError`

## 画像の向き（rotate）✅

- 整数 k（既定 0）。5 で割った余り（`-1` は `4`、`5` は `0`）。整数でなければ `RangeError`
- できた状態に U を k 回（時計回りに 72° ずつ）回した向き。写る 26 枚は U を回すと画像の上で回るだけなので、
  26 色の並びの付け替えになる。U を 1 回回すと、頂点 k の位置には頂点 k+1 にあった色が来る（辺・側面も同じ）
  - 番号 0 は動かない
  - 番号 1 + 2k ← 1 + 2((k+1) mod 5)、2 + 2k ← 2 + 2((k+1) mod 5)
  - 番号 11 + 3k + j ← 11 + 3((k+1) mod 5) + j（j = 0, 1, 2）
  - この付け替えが「手順に U を足した結果」と同じであることを、テストで確かめる
- 順：作り方（alg・case・state）→ 向き → 上書き（上書きの番号は回したあとの位置）

## 見た目の指定（Appearance）✅

| 項目 | 既定 | 検証 |
|---|---|---|
| `size` | 200 | 0 より大きい有限の数（`RangeError`）。整数でなくてもよい |
| `lineColor` | `#000000` | 色の検証 |
| `background` | `null`（透明） | `null` か色 |

- 細い線 `size / 100`、太い線 `size / 50`（どちらも小数第 2 位に丸める）

## 画像の形（Geometry）🔒

- 大きさ 1 のときの点の表（`research.md` R5）。サイトの `geometry`・`stickers` と同じ多角形を作る
  - U 面の中心の五角形、U 面の角・辺 10 枚、側面の上段 15 枚
  - 太い線：U 面の外周の五角形、側面の外周の五角形、側面の区切り 5 本
- 描く順はサイトと同じ（中心 → 角 0・辺 0 → … → 角 4・辺 4 → 側面 辺 0 の左・中・右 → … → 辺 4）

## ケース（CaseEntry）✅（`megaminx-image/cases`）

| 項目 | 内容 |
|---|---|
| `name` | ケース名（PLL `A1+`、OLL `1A` など）。種類の中で重ならない |
| `group` | グループ名（PLL `A`〜`Z`、OLL `1`〜`53`・`1C` など） |
| `alg` | そのケースを揃える手順（`case` に渡すとケースの画像になる） |
| `setup` | 揃った状態からそのケースになる手順（`alg` に渡すとケースの画像になる） |

- `PLL_CASES`（151 件）・`OLL_CASES`（259 件）。並びはサイトのデータと同じ。サイトから書き出して作る
  （`research.md` R4）。どのケースも、`case: alg` と `alg: setup` で同じ 26 色になる（正解データで確かめる）
